## 完整用户流程

原“更多笔记操作 → 导入”和笔记列表文件拖放统一进入导入工作台。选择文件只在本机解析，逐项显示格式说明、可阅读正文预览和错误；用户选择项目、修改标题、选择完整目录路径，再明确确认导入。确认时先保存本批所有所选项目的内容和稳定身份，随后逐项创建独立笔记，显示成功、确定拒绝、未知和未开始的状态。工作台不是一组临时总数提示。

成功项可查回当前状态并打开真实笔记。打开复用 `useGuardedNoteOpener` 与 App 原来的保存／放弃／取消对话，不关闭工作台后再绕过草稿保护。取消保持原笔记和工作台；成功打开才关闭工作台。选择代次、组件生命期和独立 AbortSignal 共同拒绝迟到导航。原笔记的编辑、手动／自动保存、原生退出保护保持。

停止、关闭、卸载或重启不会自动继续发送后续项目。已发送但没有确定响应的项保留原请求查回；已经确认且尚未开始的项可使用原请求继续，也可明确取消。未确认的预览不会冒充已持久化批次，界面说明需重新选择。重新打开只读本地记录，不自动 POST。

## 读取和转换边界

支持 `.md`、`.txt`、`.docx`、`.doc`、`.xlsx`、`.xls`。文本严格解码 UTF-8 或带 BOM 的 UTF-16；空文件、非法编码、二进制内容、格式与扩展名不符、目录／特殊文件、不可读取文件分别报告。原文件不改写；共享／设备路径须先保存到本机普通目录。每批最多 20 个不同文件，单文件最多 50 MiB；每个 worker 最多 15 秒，整批解析最多 60 秒，转换后正文及批次原文合计最多 2 MiB。超时回调尚未执行时，迟到成功仍按绝对截止拒绝。

Excel 最多 20 个工作表、每表最多 10000 行和 200 列、整个工作簿最多 200000 单元格；所有工作表均在同一笔记中展示，不只取首张。公式只采用文件中已有的值，不计算宏、公式或外部连接。导入编辑器转换还有更严格的 4000 个表格单元格、10000 行、2000 个公式和 20000 个格式标记前置预算，以及最终正文 2 MiB、20000 节点、64 层结构边界。达到任何一个限制时须拆分源文件，不创建截断正文。

DOCX／XLSX 压缩结构在 Office 解析库之前检查。最多 5000 个 ZIP 条目，每条实际解压最多 16 MiB、合计最多 64 MiB；不能只信 ZIP 自报大小。解压调用有实际输出上限，并拒绝重复条目、结构重叠、加密和不支持的压缩结构；伪报小体积的膨胀流也会被拒绝。这补充 worker 的内存预算，避免只限制 V8 堆却漏掉原生解压缓冲区。

Word 转换正文和常见格式；旧 `.doc` 使用正文文本。图片、附件、页眉页脚、批注和页面布局不作为可保真内容承诺；合并单元格、无法保留的格式及 Excel 缓存值在预检中说明。Office 外部文件访问明确关闭，预览以文本呈现，不插入原始 HTML，不下载远程资源。原 Markdown 编辑／项目模块调用的默认预算不因导入专用限制被扩大或缩减。

Office 字面值协议同时绑定实际源扩展名、`tableCellEncoding:base64-utf8-v1` 和严格的 `officeTextPrefix`。Word 前缀根据完整原文选取，真实单元格在 HTML 转换前从文档模型读取；Excel 工作表标题与单元格使用不同载体。编辑器按严格规范 base64、有效 UTF-8 与解码预算检查，在其他转换完成后才创建原字面节点。普通 Markdown、TXT 和旧版 Word 不接受这组元数据。嵌套 Word 表格或模型／HTML 表格数量不一致时明确拒绝，要求源文件改为普通表格；不以格式损失为理由接受正文改变。

主进程校验当前主窗口、主 frame 和实际应用 URL；子 frame、外部窗口、错误文档、重叠请求及他人的取消请求被拒绝。导航、renderer 退出和主窗口关闭终止自有解析。worker 错误／退出监听保留到终止清理完成，迟到错误不能成为主进程未捕获异常。`build:main` 和 watch 明确构建 `out/electron/import-worker.cjs`，原打包文件范围包含它。

## 原子创建、查回和本地恢复

`GET /api/local-import/requests/{requestId}` 返回现有研究任务收据；`POST` 接受且仅接受 `{title,content,parent_id}`。成功返回 `{status:'committed',receipt}`；只有明确的预检或已回滚的前置拒绝返回 `{status:'rejected',request_id,reason,message}`。数据库、提交、读取或传输失败仍是未知结果，不通过错误文字猜测回滚。

请求身份为规范 UUID v4，指纹为 `SHA256(title + NUL + parent_id + NUL + content)`。输入禁止重复 JSON 字段、非法 Unicode、危险链接、未注册节点和超限结构。既有研究／模板的节点白名单保持；导入专用验证通过后才复用 `FileDAO.CreateResearch` 的原事务：收据预留、完整目录链、同目录大小写同名检查、新建排序、文件和全文索引一起提交。数据库 schema14 不变，无新增依赖。

同 ID、同载荷再次请求返回原收据；同 ID 换正文、标题、目录，甚至改成无效请求，都不能重用为新任务。已删除或已不存在的笔记保持原收据，不能复活。查到历史收据只证明创建曾完成；打开仍读取现在的真实文件，拒绝目录、已删除和错误身份。

每项提交前先可靠保存本地请求与完整正文，确认实际写入后才发 POST。无法读写或回读验证本地记录时停止新提交；成功响应后的记录写入失败也保留未知恢复路径，不掩盖错误。结果尚未确认时不能改 ID、改正文或清理记录。确定拒绝可显式返回预检修正；已确认记录可清理但不删除笔记。

损坏记录保留原文，提供导出原记录与同一请求的有效备份恢复；恢复检查存储 key、UUID、载荷指纹和可读原身份，并须明确操作，不静默覆盖。恢复后先查回，不自动发送。没有足够信息证明已提交或未开始的损坏项保持阻断，不能靠丢弃身份来假称修复成功。
