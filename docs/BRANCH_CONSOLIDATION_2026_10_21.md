## 安装验收模块的合并边界

合并保留产品基线的全部 1577 个文件，收录安装分支独有的 103 个文件，并补齐七条生成验收器路径的 ignore 规则。新增内容包括安装工作流、生命周期与各本地模块的验证器／拒绝测试、版本来源核验脚本及固定历史反例输入。原产品工作流、`src/`、`electron/`、`server/`、版本、锁文件与保存／退出保护均保留当前产品内容。

安装分支的三个导入共享脚本仍是 4.232.0，而产品对应脚本已是 4.235.0。整合适配必须同时证明实际源文件与产品 pin 匹配、仅版本字段发生允许的转换、逆变换后精确恢复原受保护模板，并继续拒绝正文篡改、错误版本和错误 pin。历史模板哈希及原拒绝断言不能被放宽。

安装导出夹具同步当前合法同名干场景：`EXPORT102 重名.md` 与 `EXPORT102 重名.txt`。它们保持不同合法源标题，并继续在导出时验证同名干的冲突消解、失败重试和正文／附件证据。

固定 4.219.0 旧安装包继续作为目录截断缺陷的反例，17 个分片及 manifest、README、`.gitattributes` 全部保留。逐分片与顺序拼接核验结果为 104197801 字节，SHA-256 `b3fab086b8f34f2dd7025223e8322a80b2e0634bfbc88631b25ad2d0d727b43a`。这些是测试输入，不进入应用的现有打包文件列表；其源码检出体积约增加 104 MB。

## 执行与验收

安装工作流继续只在 `ci/local-installation-2f86` 的 push 上执行；源码归入 PR 后，产品开发分支不会自动发起安装、卸载操作。原 20 分钟预算、28 个生命周期门槛、9 个产品进程、6 次原生正常退出和 6 组数据比较要求继续有效。

`reading-mode-installer-pin.json` 保留已有 4.234.0 / `d3f47277` 的历史真实记录。它不代表当前 4.235.0 安装包；当前 CLI 必须在任何下载之前拒绝该过期输入。取得当前产品实际通过验收的 EXE、原始 run/artifact 身份、大小与摘要后，才能在安装执行分支填写真实 pin；合成测试数据不能写入实际 pin 文件。

本次验证范围是分支内容归并、完整产品回归和安装准备／证据拒绝合同。具体执行结果记在本次 PR 检查点中。本次整理不会把尚未完成的 2F.102 真实 Windows 导出与新安装包生命周期宣布为已验收，也不会开启下一个产品模块。

原分支继续保留作来源追溯。后续以本 PR 中的验收源码为维护入口，再同步实际安装执行所需的真实版本来源，可减少两条分支长期复制导致的遗漏。
