# 4.49.0 — 证据连续核对与原位返回

功能基线：`e36b275980c9a1868c23f696a6e156bba68f7b07`（4.48.0）。开发分支：`feature/ui-redesign-v1`；不改动 master。

## 使用

项目 → 结构 → 实体智能分析 → 正文证据回看。筛选后打开章节或点击“定位此处”，编辑器上方显示连续核对栏。

- 上一证据章／下一证据章：按进入时的完整筛选范围打开相邻章节，不限于当前页；这是整章导航，不是逐条命中自动定位。
- 返回证据列表：经现有保存／不保存／取消确认后，恢复原项目、实体、来源、卷、搜索条件，并按章节 ID 找到对应页，滚动和聚焦到证据卡片。
- 标记已核对：只记录本轮人工核对进度，不接受关系建议，不修改正文；再次编辑本章会移除标记，保存后可重新标记。
- 结束核对：清除本轮状态及待处理精确定位。核对状态仅驻留当前窗口内存，重启或刷新不会保留。
- 同一筛选范围再次进入保留仍在范围内的已核对 ID；切换实体、项目或筛选范围开始新一轮。
- 范围中章节被删除、实体／项目不再存在或不再满足筛选时明确提示，不擅自恢复到另一个项目。范围最多 10,000 章，超限仍允许普通打开。
- 源码面板开启时拒绝核对导航，不关闭或丢弃未应用的 Markdown 修改。

“核对”不是永久校对结论，也不是关系成立证明。元数据只包含必要的 ID、标题、筛选和进度，不缓存全文或写入数据库。

## 连带修复

1. 打开笔记的异步请求采用最新请求优先，取消及离开页面会使旧请求失效；读取完成后使用最新的未保存确认逻辑。
2. “不保存”离开笔记后同步清除界面的旧脏状态，避免下一次打开章节重复弹出旧草稿提示。
3. 编辑器仅在当前章节实际读取完成后挂载，避免先用空内容消费证据定位并误报过期。加载失败不可编辑，提供重试；加载中不允许把空内容或上一章内容保存到新章节。
4. 修复 A → B → A 与 StrictMode 重放中的过期响应竞争；切换自动保存偏好不会重新加载当前草稿。

保留原有 4.48.0 的过期证据拒绝与精确定位规则，没有放宽正文校验，没有新增生产依赖或删减旧测试。

## 浏览器验证与边界

Chromium 装载实际打包前端，使用内存测试数据与 API／存储替身验证：第 3 页别名证据定位至第 13 章的准确文字；编辑后取消返回保留草稿；保存后恢复项目／实体／来源／未分卷／第 3 页；下一证据章进入第 14 章；1440px 深浅主题，以及收起侧栏的 640px 核对栏无横向溢出。未捕获页面运行时异常。

浏览器环境不允许访问本地地址，因此采用离线装载，而非连接真实 Go 后端。该检查不等于 Electron／Windows 实机端到端验收。Windows 安装／卸载、打包资源和后端检查应以最终提交对应的 CI 为准；真实 Windows 高 DPI、中文输入法和系统对话框仍需人工复验。

原有 KaTeX 测试文档模式、React act 环境及 Lexical 加载时上下文告警和构建包体积警告仍存在，没有宣称零告警。
