# 2F.116 本地界面控件与视觉一致性整改（候选，未验收）

## 用户确认的范围

本阶段来自用户明确指出的输入框与按钮不对齐、重复手写基础控件及随意叠加边框/阴影问题。不是新业务功能或云端模块。基线是 master `1c8ec5689847a580ce307b9157fbbc8c1ac43a8f`，产品基线版本4.248.1；本候选尚无正式发布版本。

完整整改范围为设置、主题方案、标签、文件夹、回收站恢复、统计、重复检查、双笔记比较、历史中心、附件检查、待办、导入、导出、备份、快捷键、命名/改名、确认、文件选择和工作区包面板，共19个已有页面/弹窗。范围之外的编辑器内容节点、保存/草稿/退出保护、服务端及数据库保持不变。全应用还有其它界面，本候选不能被描述为所有页面已全面整改。

## 实现约束

基线没有Ant Design/MUI等通用UI库，也没有统一的Button/Input React组件。复用原`.btn`、`.input`及主题变量，提取`src/components/ui/Controls.jsx`作为单一基础控件入口，不新增依赖或第二套视觉主题。四种组件继续输出原生button/input/select/textarea，不引入额外DOM包裹、状态存储或写入路径。

297处控件引用接入统一入口。保留既有事件、ref、label、aria、表单、禁用和受控值；普通按钮默认type=button，原显式submit保持。checkbox/radio/file/range/color/hidden不套用文本输入几何。列表选中项、图标和文字操作仍保留各自语义，不强制全部画成方框。

普通操作与单行字段采用36px标准高度，紧凑操作28px；统一13px字号、18px行高和主题圆角。长操作文案可换行，按钮不以固定高度裁切；多选和多行字段保留内容高度。工具栏原有紧凑覆盖不被全局最小高度挤大。命名框、快捷键搜索采用同一复合输入样式，仅一层边框及焦点提示。

页面CSS保留布局与状态，不重复定义基础控件的边框、背景、字号、padding。筛选栏标签与控件纵向分组，操作按钮与字段底部对齐；复选/单选标签继续横向排列。设置入口采用稳定操作列，小窗口允许换行。浮层使用既有阴影变量；普通设置卡片与备份内部面板不再叠加装饰阴影。语义性的键盘焦点、选中状态、错误警告和差异行标记不删除。

## 数据与交互保护

不改业务处理函数、接口、状态机、数据序列化或存储键。代码审查通过还原控件标签/导入后的AST比较确认19个页面原有逻辑表达式保持。该静态检查不是业务或视觉验收替代品。原组件/集成/默认Vitest、UI、Electron、Go与构建均须保留；任何失败保留原件，不删断言。
