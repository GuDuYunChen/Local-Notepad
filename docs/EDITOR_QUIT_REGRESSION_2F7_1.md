## 先处理上一阶段未通过的检查

PR CI #1212（run 36223362787）已失败，而非仍在运行：main/preload 与 renderer 构建通过，UI 回归为 1005 passed / 6 failed。失败分为两组：

- TextEditor.test.jsx 两项保存协调测试使用了与请求正文不同的成功响应（saved-one / saved-two / 空正文），与 2F.7 新增的严格保存回执检查不相容。本次只纠正成功场景的三处响应正文，原有协调/去重断言保留，不放宽正式回执校验。
- TextEditorLoad.test.jsx 四项加载测试被上一用例留下的干净正文缓存影响。新增的退出检查/卸载清理原先无条件把已加载正文写入缓存，刷新 editedAt。localStorage.clear 不清除内存 fallback，旧的干净正文因此被当成更新的本机编辑。仅清理测试缓存会掩盖正常卸载/重新打开时的同类缺陷，因此修改正式生命周期缓存条件，保留原加载测试不变。

## 正式修复

TextEditor 退出检查与卸载共用 cachePendingDraft：只有当前文档已加载、未删除，并且正文确实不同于已确认基线，或该文档仍有未结束的写入时，才补写恢复缓存。

- 单纯关闭或检查干净文档，不创建新草稿，也不刷新已有缓存的时间。
- 防抖未触发的脏正文仍保留。
- 用户把正文改回旧基线，但同一文档的旧保存尚未完成时，仍保留回退后的正文，不能把它误当成无须保护的干净状态。
- 其他文档的在途保存不能使当前干净文档被重新缓存。
- 不删除用户已有缓存、不扫描/重放其他文档，不改变缓存格式或持久化存储实现。
- 保存回执的文档 ID 与正文必须匹配；缺失、错 ID、错正文、缺失正文仍按失败处理。迟到保存响应与排队回退的已有保护不变。

本轮没有扩展同步协议、改动后端退出算法或新增数据库迁移。缓存不是数据库保存成功的凭证；既有缓存的整体合并策略、强杀/断电恢复不在本轮范围内。
