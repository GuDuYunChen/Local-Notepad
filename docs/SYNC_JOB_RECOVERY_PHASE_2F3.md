# Phase 2F.3 — 持久化任务退避与不确定写入保护

基于 8109f278 / 4.189.0 / schema 13。本阶段不提升包版本、不改变数据库 schema，不修改原有 manifest、对象、附件、远端锁和三方合并算法。

## 已接入实际应用入口

`main.go` 创建同一个 `RecoveryRunner`，提供给 HTTP 同步控制器、设置写入控制器和 `RunRecoveryScheduler`。应用启动不再运行旧的 `RunAutoScheduler`。旧 Engine API 仍保留供算法测试和内部复用，不代表它们自己具备任务恢复保护。

状态机位于无外部依赖的 `internal/syncjob` 包，实际引擎适配器位于 `internal/syncengine/recovery_runner.go`。

## 两阶段执行与保守恢复

1. 首先只读预检连接、已绑定远端身份与 manifest/对象结构。
2. 已分类的临时网络错误和 408/429/500/502/503/504，仅在这个只读阶段安排后续任务尝试。
3. 基础间隔 60/120/240/480/960/1800 秒，之后以 1800 秒为本地上限。不会短于用户配置的同步间隔；服务端更长的 Retry-After 不被缩短，绝对截止时间会持久化。异常大值只延后，不溢出为立即重试。
4. 认证、权限、证书、未知错误等暂停自动尝试；用户修复后可手动验证/执行。
5. 调用 Engine.Run/Resolve **之前**先持久化 applying 标记。保存失败不允许进入写入阶段。
6. 一旦进入 Engine.Run/Resolve，任何失败都视为“结果待确认”。即使错误来自创建目录、远端锁或网络，也不在此猜测是否无副作用。
7. 自动调度不会重跑 applying/review_required。进程重启遇到 applying 也同样阻止自动执行。
8. 用户在同步中心核查两端数据后，可点击“执行同步”并明确确认。请求携带 `acknowledge_uncertain=true`，重新只读预检，再调用原有同步算法；这不是自动回滚或事务重放。
9. 只读连接检查成功不会清除不确定写入标记。失败的只读检查也不会把不确定写入降级成可自动重试状态。
10. 成功任务清除失败计数并记录 last_success_at；完成记录保存失败仍保留之前的 applying，不能误报完整成功。

## 本机记录与作用域

- 记录位于应用数据目录 `sync-runtime/job.json`，独立于数据库/工作区便携包。
- 只记录版本、状态、连续失败次数、尝试/成功/下次时间及固定错误类别；作用域为设备/provider/endpoint/username/local remote root 的 SHA-256，不含密码或正文。
- 临时文件写入、Sync、关闭后重命名替换；不先删除旧标记。
- 拒绝已知目录/文件符号链接、超限文件、格式/版本异常记录；失败时停止同步而不是假定状态为空。
- 同一作用域的等待在进程重启后继续生效。改配置不会自动消除尚未确认的写入。
- 显式重新绑定仅在原操作成功后重置本机任务记录，仍不删除本机或远端内容。

## 并发与 UI

手动同步、自动同步、预演、连接检查、冲突解决和重新绑定共享操作闸门。设置 DAO 写整行，因此设置写入也共享该闸门，避免旧设置在同步期间覆盖连接配置。忙时立即返回“同步操作正在执行”，不排成长队；这可能要求用户稍后重新保存设置，笔记编辑接口不受该闸门限制。

状态 API 保留旧字段，增加 recovery 快照。UI 显示任务恢复状态、最近确认成功和最早重试时间，与 2F.1 的 UI 状态读取重试明确分开；旧状态导致的未确认重试会被后端拒绝，UI 随后重新读取状态。

## 明确边界

- 这是单个受管本机后端的任务级闸门，不是分布式锁或多进程互斥协议。
- 支持进程重启后的记录恢复，不宣称断电、损坏磁盘或恶意本机文件修改后的完整持久性。
- 记录不随 .lnw 跨设备迁移；工作区恢复、手动删除记录、旧版本后端直接运行不受本状态机保证。
- 仍未新增 Engine 到每个 WebDAV 请求的端到端取消，也没有改变远端锁过期回收。
- 不自动重放可能写入的同步尝试；不通过单次只读检查宣称已确认先前提交结果。
- 笔记编辑与同步算法本身的并发一致性、跨机器同步锁租约及提交结果对账，仍需独立实现/验收。
