# 2F.88 / 4.221.0 本地每日笔记完整模块

基线为已验收的 7b133bf / 4.220.2（PR #2 最终记录 6144573069）。本模块不是云同步，也不重做历史恢复或回收站。

## 用户完整流程

侧栏每日笔记 → 本机日历／月份或日期跳转 → 读取根目录日期记录 → 打开已有记录或明确点击空日期创建 → 原编辑器编辑、Ctrl+S／自动保存与退出保护 → 再次进入日历读取已保存记录。

已有记录只打开，不覆盖正文。日历以本机民用日期为准，验证真实日期、闰年、月末与 0001–9999 年边界。根目录之外、回收站、无效日期标题不冒充当前每日笔记；根目录同名文件夹与历史重复记录明确拒绝，不随意选择一份。最近列表以 14 项分页，并提供完整日期筛选；标题和位置仍沿用根目录 YYYY-MM-DD 的既有约定。移动或改名后不再归类为每日笔记。

## 读取、取消和未确认结果

分页读取使用原 compact API；任何页面错误、非法格式、重复 ID 或超过 100 页 / 10 秒预算，都拒绝不完整列表，不显示假空。进入和翻月不自动创建今日记录。

打开先 GET 只读核对，缺失后才使用 POST 创建。全组件共享一次操作占用，发出前再次检查停止信号，关闭面板不采用迟到结果。已发送创建的超时或停止不是数据库回滚；未确认日期在当前应用会话保留。核对只 GET，不自动重发；负向核对仍不证明原创建失败。重新创建需要明确确认并再次读取，已有内容不覆盖。编辑器交接失败说明记录仍在，不触发重复创建。

后端在一个事务中执行 INSERT … SELECT … WHERE NOT EXISTS，避免先查再创建的竞态；只承认单一、非文件夹、未删除的根目录记录。使用原 files 表、FTS 触发器和排序规则，无 schema 迁移。原 GET 自动创建入口保留兼容，新前端使用 POST；read_only=1 永不创建。非法日期在访问数据库前拒绝；返回 no-store。

## 防复发与验证边界

保留历史 46 项产品／环境记录和 12 类助手执行问题，以及 4.220.2 的已有验收。当前新问题包括原每日读取错误仅写 console、格式日期误判、根目录身份混淆及同时创建请求。源代码、测试、当前 HEAD CI、原生运行与安装包分别核验，不能把存在脚本或静态检查当通过。

新增共享核心 Node/Vitest、实际 React DOM 和 Go/SQLite 回归；Windows 脚本通过原侧栏进入、真实创建和保存、重新打开、并发打开、非法日期，以及在服务提交后丢弃 POST 响应再只读核对。原保存、历史恢复、回收站和正常退出测试保留。无替换生产 Go、SQLite、响应成功或程序化点击替代真实鼠标验收。

本地离线界面检查与直接 SQLite SQL 对照不等于生产 Go 或 Windows 已运行。完整项目及当前提交安装包必须另外通过后才交付。标准 minor 版本 4.221.0，679 依赖节点与 schema14 保持。
