# Phase 2F.15.1 — 总览恢复警示与读取依据保留

## 复查发现

基线为 `364d7e2dddd909f8886d43efe4206b96a932ff26`，继续 `feature/knowledge-os-phase2` / Draft PR #2，不合入 master。

发现两项显示层遗漏，不能因上一阶段 CI 已通过而跳过：

1. 总览主标题优先显示等待或旧状态时，会越过阻断 / 暂缓分支。最近状态与恢复详情一致时，原来的差异提示也为空，导致已有的恢复保护阻断或预检暂缓信息在总览中消失。
2. 写入待确认的标题优先级最高，但其下只显示读取时间和通用说明，未独立保留“正在刷新 / 上次读取结果”的依据。用户难以同时看见写入风险与快照新旧程度。

## 修复边界

保持原有主标题和建议区域的优先级；额外保留被主标题遮住的阻断 / 暂缓警示，明确这些是**已读取快照中的提示**，不声称当前仍在阻断，也不把等待或刷新解释为保护解除。矛盾的最近状态与恢复详情分别保留，仍提示详情缺失或不一致。

在计数下方始终显示白名单化的读取依据：尚未读取、上次结果、正在刷新或已读取快照。未知输入不转成成功，不泄露错误原文，不生成重试时间，不把历史成功时间当作当前完成。没有改动状态读取器、导航逻辑、父组件、密码、后台同步、写入、冲突确认、退出保护、依赖、版本 `4.189.0` 或 schema `13`。
