# Hotfix — 已放弃或已恢复笔记导致退出阻塞

## 用户报告与范围

用户在 Windows 遇到“退出未完成，窗口已保留 / 仍有切换前或已关闭笔记的正文未确认保存”。基线为 `40c1d2f0620f7424670532975fb10e76746940d9`。本次暂停后续功能阶段，保留原分支 `feature/knowledge-os-phase2` 和 Draft PR #2，不合入 master。

## 已确认的代码路径

1. App 的“不保存”仅调用 clearCache、清理父组件显示标记，未释放退出注册表中的对应正文；TextEditor 的正文引用也仍是放弃前内容，切到设置等工作区卸载编辑器时可能重新写回缓存。
2. 编辑器发出与已确认正文相同的 onChange（包括撤销回原文）也无条件标记待保存。随后正常离开编辑器，退出时存在没有活动参与者处理的残留项。
3. App 把 onLoaded 返回的恢复草稿当成数据库已保存正文，导致恢复草稿的离开确认可能被跳过。TextEditor 已保留的真实数据库基线与父组件基线不一致。

截图本身不证明用户具体经过哪条路径；上述为代码确认并加入针对性复现的路径。

## 修复与保护边界

新增精确 discard 操作，仅由明确点击“不保存”的当前草稿调用。存在尚未完成的保存时拒绝放弃和跳转，不用取消请求冒充回滚。成功时清理当前草稿登记和缓存计时器，正文引用回到实际已确认基线，避免卸载重新缓存。不能删除别的笔记或已更新为其他内容的登记。

与数据库基线完全相同且没有在途保存的编辑通知不再留下待保存项；有在途旧写入时仍保留保护。恢复缓存仍作为草稿显示，但 App 的已保存基线取自 TextEditor 的数据库基线。

不关闭退出保护，不清空全局注册表，不批量保存历史缓存，不篡改保存成功回执。未保存正文、失败或未确认保存、其他笔记的未解决草稿、章节结构确认、源码模式、IME、Electron 退出握手与后端退出保护继续按原规则处理。同步、数据库 schema13 和版本4.189.0不改。

## 验证

新增14项Node测试，提交前本地执行通过。新增真实App/ConfirmDialog/TextEditor/草稿缓存/退出桥接的10项集成场景；只替换富文本输入和无关导航面板，不模拟放弃逻辑或退出结论。覆盖“不保存→设置→退出”、“不保存→其他笔记→退出”、缓存计时器/卸载、撤销、相同正文通知、恢复缓存、取消、在途保存、实际保存失败和其他笔记残留。
