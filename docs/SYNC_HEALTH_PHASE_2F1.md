# Phase 2F.1 — 同步中心健康状态与只读状态恢复

基于 4.189.0 / schema 13。本阶段不修改后端同步算法、数据库、远端锁或凭据存储；包版本暂保持 4.189.0，不将整个 Phase 2F 宣称完成。

## 修复

- 后台刷新按字段保护尚未保存的 endpoint / username，密码只来自当前输入，不从设置响应回填。
- 用完成后调度的单次定时器替代 setInterval。同一时间至多一轮有效状态读取；操作开始时取消并作废旧请求，防止旧结果覆盖写入后的状态。
- 状态读取超过 12 秒超时。首次失败等待 30 秒，再按 60 / 120 / 240 / 300 秒退避，300 秒封顶；成功恢复后回到正常 15 秒状态读取周期。
- 正常周期只在已启用自动同步时运行；首次加载失败也会退避恢复。关闭面板会撤销请求和定时器。
- 后台读取失败只显示常驻提示，不反复 toast。保留上一次完整快照并标为过期，支持“刷新状态”立即重试。
- 展示模式、冲突、最近尝试、状态读取时间和重试时间。last_sync_at 目前也用于后端失败记录，因此标为“最近同步尝试”，不当作“最近成功”。
- 只读连接检查结果常驻显示，并标明检查时间及“不能证明写入权限或持续在线”。编辑连接草稿后使结果失效；有未保存草稿时不对旧的已保存目标误做连接测试。
- 配置写入成功而随后的状态读取失败时，明确区分“操作已完成，状态尚未确认”，不再直接显示完整成功反馈。

## 边界

本阶段的退避只用于 UI 读取 `/api/settings`、`/api/sync/status`、`/api/sync/conflicts` 及凭据状态。不会自动重试 `/sync/run`、开启同步或冲突裁决。

后端真实 WebDAV 同步请求的失败分类、持久化重试状态和恢复策略不在本提交范围内，仍需后续独立实现与验收。
