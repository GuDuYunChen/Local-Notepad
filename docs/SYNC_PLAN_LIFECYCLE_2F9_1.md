## 问题与修复

### 预演响应不返回时一直占用页面操作锁

原 preview 直接 await API，共享 API 没有客户端超时，也没有传入可在卸载时取消的 signal。即使服务端有 30 秒协作式读取预算，连接或响应一直挂起时，页面仍可能一直停留在「预演中…」。

增加独立的只读预演等待边界：35 秒客户端等待预算（服务端 30 秒外留 5 秒响应余量），以及「停止等待预演」按钮。超时、主动停止和卸载都会清理计时器 / 监听器，并向本次预演请求传递 abort。即使底层忽略 abort，等待也能结束；迟到的成功或失败不会更新页面、覆盖后续预演、弹出第二条结果或重新发送请求。

已有快照在重新预演开始时按原规则失效；等待失败后保留其内容供对照。停止等待仅表示客户端不再接受本次读取结果，不保证服务器只读任务已经终止。不会调用 `/api/sync/cancel`、关闭自动同步或撤销其他任务。

### 预演等待时漏掉任务结束通知，也可能因自身预演结束而误报失效

原 refreshAfterTask 在父页面 busy 时直接跳过处理，既没有推进快照变化计数，也没有补刷新。活动面板又只通知「有任务结束」而不传递已结束任务的类型，所以空闲时观察到预演 / 只读连接检查结束，也会把刚产生的快照标为失效。

现在活动面板传递其已验证的旧任务快照。可能写入的任务结束时，即使父页面仍在等待，也立即使旧快照和在途预演失效；状态读取暂时推迟，在当前操作退出后合并补做一次。只读 `plan` / `check` 的结束本身不构成数据改变证据，但后续状态读取实际观察到变化或失败时，仍按原规则失效。未知类型保守处理。

不增加任何自动预演或自动写入。执行同步与显式冲突处理不使用这个客户端读取等待器，已有写入结果待确认、人工确认和恢复保护不变。
