## 用户流程

侧边栏“搜索笔记”或 Ctrl+Shift+K → 全局检索。保留 Ctrl+K 快速切换及其携带关键词入口。

1. 完整检索：目录及子目录、来源、置顶、大小写、相对日期和排序组合，每页 20 篇。标题、普通正文、代码、链接标签、图注及公式内容按字面匹配，结果带有限上下文及精确提及总数。
2. 常用检索：展开“常用检索”，命名并明确保存当前条件。在本机再次打开可读取；保存不含结果、正文、页码或过期版本指纹。每份独立键，最多 40 条（损坏记录也计入容量）；不自动写查询历史，不静默覆盖同名条目或淘汰旧记录。应用前检查条目未变化，“最近 7/30/90 天”按本次时钟重新计算，回到第一页。旧目录消失时明确报错，不扩大到全库。
3. 连续查看：预览栏“上一结果／下一结果”跨页读取，向前跨页选末条、向后选首条，不直接打开或修改正文。手动翻页选首条；同一页打开正文再重新打开检索时保留选择及列表滚动位置；当前没有自动返回检索的编辑器专用按钮。筛选或正文版本变化不使用旧结果。相对日期在刷新、重新打开和应用保存条件时重新计算。

未保存草稿仍通过原保存／不保存／取消保护。只有普通文字提供可验证的字符定位，非普通文字不伪装精确定位。保存失败保留输入；删除检索需要确认，只删除该条条件，不删除笔记。读取失败不显示为空列表。另一窗口的存储事件和重新获得焦点都会刷新列表，删除前复验原内容。

常用检索仅存放在当前应用/浏览器用户数据中，不是云同步，不随正文 .db 备份或核对存档 JSON 迁移。关闭检索释放返回正文节选；没有自动持久化搜索词的历史列表。

## 解析缓存与准确性

FileDAO 持有进程内 LRU 解析缓存，按当前原始正文 SHA-256 寻址。每次请求仍在同一数据库读取事务内读取当前元数据与正文，并重新生成范围指纹；不是旧结果缓存，也不是持久化全文索引。

相同正文的 JSON 提取和 Unicode 规范化可以复用；正文修改（包括同秒、相同长度）、目录调整、删除和重命名仍参与当前判断。旧指纹的分页拒绝继续。查询只匹配当前活动行，缓存不会使已删除笔记重新出现。

默认最多 2,048 项和 32 MiB 的估算保留数据（含字符串及固定开销估算），不承诺整个 Go 堆的精确上限；过大单项不缓存。使用互斥保护 LRU，避免返回可变切片别名。并发未命中允许重复解析一次，统计仍按实际调用返回。缓存不落盘；旧正文可能暂留进程内，直至淘汰或后端退出。冷启动、超过缓存工作集的大库、反复修改可能仍完整解析，磁盘读取与逐篇匹配并未消除。

回执增加 cache_hits 和 parsed，界面显示本次复用/新解析数；它们不是“数据已经备份”或“搜索速度保证”。标题检索和空关键词浏览不需要解析正文，但仍核验正文指纹。兼容不含这两个统计字段的旧检索回执。
