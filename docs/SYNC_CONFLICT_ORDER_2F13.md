## 确认与数据边界

排序作用于筛选结果的新数组，不修改服务端返回的冲突记录或冻结索引。保留原数组位置与冲突编号，打开对照和最终提交仍指向正确的原始记录，不以排序后的索引错配对象。

显式更改查看顺序会回到第一页，并沿用原有浏览 epoch 收起对照、撤销旧确认。排序 A-B-A 不恢复旧确认；相同内容的状态刷新不无故撤销仍可见对象的有效确认。处理中的同步 ref 锁同时阻止同一事件循环中的排序以及首尾导航，原提交/重读/取消/恢复流程未改。

首尾导航对当前筛选结果生效，在边界或单页时禁用，并将键盘焦点返回「冲突中心」标题。列表缩短后保持实际收敛页码，不因后来补充数据突然跳回已经不存在的旧页。清空筛选保留查看顺序，界面明确说明；用户可通过下拉框恢复服务端顺序。顺序仅保存在当前组件内存，不新增 localStorage、持久化偏好、网络端点、后台请求或批量处理。
