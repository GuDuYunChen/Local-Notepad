# 4.140.0 — 资料集便携备份与安全恢复

基线：`feature/ui-redesign-v1`，`6c43501109a6b5b82ea63b3da209fe0aa2b42fc3`（4.130.0）。不修改 master，不新增依赖、数据库迁移或正文写入。

## 使用入口

全局检索 → 本地资料集 → 资料集便携备份与恢复。

选择资料集后，“备份资料集及阅读记录”生成一个 JSON，包含这份资料集的全部历史条目以及已保存的阅读状态、批注与笔记级书签，不受分页、搜索或筛选影响。它不包含正文、附件、未保存的批注草稿、其他资料集、应用设置或核对存档。需保留草稿时先保存。原来的两种单份 JSON 入口仍然保留并兼容。

没有本地资料集也可以选择便携备份文件。预检显示名称、备份时间、篇数、已读、待复看、批注数和书签；明确确认后才写入。恢复不检查原笔记在本机是否存在，不创建正文，不自动打开笔记或结束正在进行的阅读；缺少正文时需要另行迁移数据库。

## 独立副本、重复导入与中断续传

恢复生成独立资料集和配套阅读记录，不覆盖同名资料集或既有批注。新副本保留原资料集保存时间和阅读记录中的历史时间。恢复目标 ID 来自规范化源资料集与已存阅读记录的 SHA-256，不包含本次导出时间；相同源组合再次备份、恢复会识别同一目标，而不是无限增加副本。

已恢复副本有有效的新批注时，再导入旧包只识别已有副本，保留本机新进度。已存在的目标内容不一致或损坏时停止，不覆盖；如果来源和独立副本均一致但阅读记录被单独删除，预检会明确显示“补齐缺失的阅读记录”，确认后才能补齐。

恢复不是跨两个 localStorage 键的数据库事务。采用先暂存新阅读记录、最后发布可浏览资料集的顺序；两次写入之间没有异步等待。第二次写入失败或进程中断时，已暂存阅读数据保留，界面不会报告完整成功。保留同一个备份文件，重新预检会复用准确匹配的暂存数据继续恢复，不重复创建副本。此版不提供孤立暂存记录的清理页面，也不声称能抵御断电或底层存储损坏。

同源新导入使用专用 Web Lock 串行确认，同时复用阅读记录的锁名；确认前再次核对资料集键集合和目标旧值。锁不可用、拒绝或五秒等待超时会停止，不回退到无锁覆盖。预检凭据由服务内部签发，过期、伪造或其他服务实例的预检不能指定任意存储键。非协作旧版本、不同 origin 或外部存储篡改不在锁保证范围内。

## 校验与容量

便携文件最多 4 MiB，资料集继续遵守 2000 篇／2 MiB、阅读记录及其单份备份遵守 1 MiB、每条批注 2000 个 UTF-16 代码单元。恢复前也验证新 ID 下的记录仍可完整单份导出。容量不够拒绝，不截断、不自动清理旧记录；40 份资料集上限包含不可读记录。

按白名单重建数据，核对配套身份、完整历史报告指纹、状态、书签、重复／非法笔记 ID 和时间格式。SHA-256 校验和用于检出数据不一致，不是数字签名，不能证明文件来自可信发送者。导出在异步计算后再次验证资料集与阅读记录，包括“原先未保存阅读记录”这一状态，避免组合成过期文件。

## 界面保护

切换来源、取消、关闭面板或外部禁用会使未完成操作失效。文件过大时不读取内容，读取失败可重试，预检不写入。取消预检后在控件恢复可用时归还焦点；避免向仍被禁用的文件选择框聚焦。恢复成功后的视图刷新异常不会被误报为存储写入失败。

## 验证范围

新增 49 项测试：服务 34 项、实际组件 15 项，保留上一版全部测试。覆盖 65 篇完整条目与末页批注、重复导入保留更新、损坏文件、范围与指纹不匹配、取消、旧预检、容量、两步写入失败和重新预检续传、原生锁协议与通知异常。

原生 Electron 检查扩展配套恢复、两个并发确认只允许一份成功、重复恢复和新进程读取配套批注／书签，沿用隔离临时用户目录，不接触用户数据。实际结果以本次提交 CI 日志为准；上一版成功不代表本版成功。

本地 Chromium 导航被 `ERR_BLOCKED_BY_ADMINISTRATOR` 拦截，未获得本版视觉截图。当前容器不能下载 Go 工具链，未完成本地 Go 全包验证；相关检查保留在正式 CI。原生 Electron 模块检查也不替代完整应用、高 DPI、中文输入法或系统文件对话框人工验收。

技术依据：Web Locks 按同源与锁名协调，取消信号只取消尚未获得的锁请求（https://developer.mozilla.org/en-US/docs/Web/API/LockManager/request）；Electron `session.flushStorageData()` 用于原生测试退出前请求写出 DOMStorage（https://www.electronjs.org/docs/latest/api/session）。
