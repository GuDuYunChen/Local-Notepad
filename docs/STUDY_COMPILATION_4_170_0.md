# 4.170.0 — 从阅读批注到独立研究笔记

基线：`feature/ui-redesign-v1` / `4ac043b42edad5d62a5999979b03f9f9fd50f9e7`（4.150.0）。本轮整合上一轮未推送的 4.160 批量标记与安全撤销；不改动 master、不新增依赖或数据库迁移。

## 使用流程

全局检索 → 阅读批注 → 跨页选择有批注的条目 → “整理成研究笔记” → 输入名称、目标目录、研究目标，选择按资料集或阅读状态分组 → 预览 → 明确确认创建。

每次 1–200 条已保存批注、文档最多 2 MiB；完整预览覆盖全部所选分页。所选条目没有批注时明确拒绝，不悄悄跳过。来源异常、快照过期、所选批注存在未保存草稿时阻止生成或提交。目标目录由已有检索返回的目录列表提供；创建前再次检查目录，后端也验证父目录，不会擅自改存根目录。

## 文档内容

创建独立的可编辑笔记，保留批注原文、历史标题与目录、资料集名称与身份、笔记 ID、原序号、人工阅读状态和批注保存时间。相同笔记在不同资料集中分别保留来源，不自动去重或合并观点。批注换行在编辑器内统一为 LF。

内容由 Lexical 的 heading、paragraph、text、linebreak、wiki-link 结构生成；不将用户内容当成 HTML。来源 WikiLink 使用原笔记 ID，创建后可点击回到当前来源笔记；来源被删除或迁移后 ID 不可用时，链接不能凭空恢复正文。预览不读取源正文，也不验证源正文当前是否与历史批注相符。

提供“研究目标”和“我的结论与下一步”区域。这里只整理已有的人工批注，不自动总结、补充事实、推断结论或确认资料真实性。支持下载完整 Markdown 草稿；下载文件保留可读来源身份，但不伪造跨应用可用的 WikiLink URL。

## 创建与草稿保护

复用现有 `POST /api/files` 创建端点，只新增笔记，不使用 PUT、覆盖或删除正文。创建成功会通知资料库刷新，但不自动切换当前正文、不清除批注草稿或改写人工阅读状态。创建新笔记会为新笔记建立来源链接元数据，不修改来源文件正文。

“打开新研究笔记”单独经过 App 原有保存／不保存／取消流程。取消仍保留创建成功回执与原正文草稿，能够再次打开，不会再次创建。同一份预览在请求处理中拒绝重复确认，成功后重复调用返回同一回执，不再次 POST。

请求发送前再次校验来源与未存草稿。POST 已经发出后，关闭窗口、网络中断、15 秒超时或响应不完整都不能证明后端未写入：报告“结果尚未确认”，停止本窗口内自动重复提交，并保留标题与可下载的研究草稿。应先在资料库检查创建结果。现有端点没有持久化幂等键，不能承诺跨重启、外部并发或重新生成预览后的全局 exactly-once。不要将“取消请求”理解成回滚。

创建期间或创建之后来源另有修改，不自动更新已经提交的研究笔记；文档标明所用来源快照与整理时间。来源校验和数据库写入不是跨存储事务。文档和 Markdown 未加密，可能包含私人批注与自己填写的研究目标。

创建回执、预览以及研究目标输入仍是窗口内存状态，退出应用后不保证恢复；正式创建成功的笔记进入正文数据库，随后沿用普通笔记保存与备份流程。已经下载的 Markdown 由用户保管。
