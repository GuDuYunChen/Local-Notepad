# Phase 2F.38.2 — S3客户端值及嵌套格式化脱敏修补

基线7f6787575b9e370aed38fdec6768d83e45cd18c8 / tree b020299745198d81b1ba1cb724c597cc90dcde80。仍为feature/knowledge-os-phase2 / Draft PR #2，不合master、不发布生产。复查发现SREAD-02，先修本阶段，不开始2F.39。产品4.195.1/schema14不变。

## 已复现问题与范围

原ReadClient的Format只定义在指针接收者上。使用合成AccessKeyID、SecretAccessKey和SessionToken，对`*client`的值用`%v`、`%+v`、`%#v`格式化，三个子测试都检测到输出含凭据并失败。没有打印失败输出或标记原文，没有读取真实用户凭据，也没有证据表明发生过生产泄露。包仍未注册生产provider；这是基础包的日志暴露风险，不是已确认的用户账号事故。

扩展回归表明，私有包装字段会使fmt跳过内嵌值的格式化方法；仅改值接收者不足，凭据改成普通指针后，`%s`/`%q`的递归诊断仍可展开内容。中间候选完整回归非零失败，原日志保留，未推送该候选或删除这些反例。

## 最终修补

ReadClient.Format改为值接收者，让值和指针均实现fmt.Formatter。内部将构造时的凭据值快照保存在私有、纯读取闭包中，不再把明文结构体作为可被fmt递归展开的客户端字段。闭包没有外部凭据发现、环境读取或网络操作；每次签名读取相同不可变快照，调用方后来修改其Credentials变量不影响客户端。nil凭据存储也在请求前返回ErrConfig。原公开构造/GET接口不变。

直接格式化值或有效指针使用固定占位符；零值及nil指针通过fmt打印不会产生panic诊断。标准fmt、log、slog的值/指针、容器和私有包装回归不得出现明文或十六进制合成凭据。fmt仍可能在被绕过的方法路径显示非敏感结构或地址；本修补不是保证任意反射工具、unsafe、原始Credentials字段或内存转储都无法访问秘密，更不是加密保存或内存擦除保证。

不改变请求签名算法、Content-Encoding全部同名字段检查、TLS、对象键、正文大小限制、超时/取消或只读要求。不增UI/HTTP路由、凭据持久化、List、写入删除、同步provider注册或自动同步，不连接用户桶。WebDAV、编辑器保存/退出、数据库、依赖及工作流不改。

## 回归与事实边界

保留原20项顶层Go测试；旧测试仅一处内部字段读取改为调用快照访问器，URL不含AccessKeyID的断言保留。新增8项顶层测试覆盖：三种直接值打印、双方法集/多格式、11种容器与包装×7种格式、标准log/slog/JSON、nil/零值、并发格式化零网络/零时钟调用、格式化后原对象和副本的真实loopback签名读取及调用方变量隔离、缺失内部快照拒绝。

新增回归在原实现得到55条通过/64条失败事件；失败包含父子测试并有提前返回，不能与顶层数相加。只存普通凭据指针的中间候选得到216通过/7失败事件，仍失败，未发布。最终独立包Go1.23.2执行`GOTOOLCHAIN=local GO111MODULE=off go test -race -json -count=1 -timeout 45s`，28项顶层/含子测试223通过事件，0失败/跳过；vet退出0。日志不包含实际格式化输出。

这是本地标准库包及loopback验证，不是项目Go1.24.11完整后端、Windows、React/Electron、真实桶或生产验收。当前修补仍须原8PR、push完整UI/Windows、Desktop、合并测试树和完整UI/服务/原生/桌面/安装包原产物及新增syncs3执行日志验收；完成前不进2F.39。基线八PR虽全部成功，发现本缺陷后未继续下载其全套旧产物或宣称基线独立验收通过。
