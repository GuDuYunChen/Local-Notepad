# 4.53.0 — 核对存档整包备份与导入预检

功能基线：`cbb6a4a3cc115f66e07b378d490b6967e3d9f256`（4.52.0）。
开发分支：`feature/ui-redesign-v1`。不修改 master、正文、数据库、单份存档格式、恢复规则或关系评分，不新增依赖。

## 使用入口

项目 → 结构 → 实体智能分析 → 正文证据回看 → 本地核对存档 → 整包备份与导入预检。

“备份当前范围全部存档”覆盖存档查看范围的全部分页，不仅是管理器第一页的 5 份。需要备份所有项目时，先将查看范围切换到“全部本地存档”。每个备份包包含 1 至 40 份独立存档。

备份只包含已经手动保存的核对快照及备注，不包含正文、当前未存档进度或应用设置。下载按钮只确认发起下载，不能替用户确认系统已将文件写入磁盘。范围含不可读取的存档时，拒绝生成会遗漏记录的备份，并提示先使用原有“导出存档 JSON”逐份保留原始文件。

## 预检与导入

新入口同时接受整包 JSON 和原有单份存档 JSON；读取文件只预检，不写存储或开始核对。预览显示每份项目、实体、历史时间、章节数、将新增／本地已有／文件内重复，每页 8 份。确认按钮在摘要下方，宽窗口使用多列记录卡，窄窗口自动回到单列。

重复判定比较历史保存时间及完整有效核对内容，不按文件名或存档 ID 猜测。对象属性顺序、已核对 ID 集合顺序、无文字且未标记的空备注不制造额外副本；章节顺序、原始备注文字、范围、保存时间变化仍是不同快照。此行为只属于新增预检入口；原有单份直接导入按钮仍保留原来的独立副本语义。

确认后为新增项分配新 ID，保留历史时间与人工记录；不覆盖旧存档，不修改当前核对，不创建正文或自动恢复核对。不同项目可以在同一备份包中，预览明确显示其 ID；恢复时仍需对应项目、实体与章节存在，历史已核对不沿用为当前正文已审核。

整个文件先校验，任一成员无效或未来版本不支持时，不导入其他成员。容量预检计入不可读取的本地记录，超出 40 份上限时阻止确认，不自动淘汰旧数据。文件与单份内容都有大小限制；采用已有字段白名单，不复制正文快照或运行时令牌。

## 失败与并发边界

确认前重新检查本地记录，变化则要求重新预检；逐份写入前后继续检查。取消文件选择保留原预览，取消读取、切换查看范围、卸载组件或后选文件会使过期读取失效；快速重复确认不会重复执行同一预览。

localStorage 不提供跨记录事务。本功能按顺序写入独立快照，中途配额不足或观察到外部变化会停止，显示实际成功写入、重复跳过和尚未处理的数量，不撤销成功项、不删除任何旧存档。重新预检同一文件会识别已有的成功项，便于继续导入。它不是跨窗口排他锁，也不承诺多个窗口同时确认时的全局原子去重。

同时修复存档订阅回调抛错可能将已完成的存储写入误报为失败的问题：视图订阅异常单独记录，其他订阅继续更新，真实存储错误仍正常报告。
