## 变更

1. 退出保存与 Markdown 源码面板拆成两个测试文件。源码面板的 Lexical 上下文替身不再与 TextEditor 输入夹具放在同一测试模块。
2. 编辑器测试预加载 React.lazy 对应模块，再明确等待输入控件和目标正文就绪。等待有 1500ms 测试上限，不靠固定次数的微任务推进来假定 DOM 已挂载。
3. 模拟保存的回执在 PUT 发出时捕获文档 ID 和请求正文，不从稍后可能变化、被卸载或不存在的 textarea 生成旧请求回执。
4. 输入法测试从实际已挂载输入控件发出 compositionstart，检查不写入、不冻结、不改变焦点、不触发 blur；compositionend 后使用新请求编号再次执行退出检查。
5. 手动保存与退出重叠时，明确等待第一笔请求，输入更新正文，保持旧回执与新正文分离；两笔写入各自确认前不得批准退出。
6. 缺失回执、错误文档、错误正文、缺失正文四类情况继续拒绝退出，保留未保存账本与旧基线。桥接卸载后迟到回执不得重新批准退出。
7. 清理测试自身的在途请求、桥接、React 根、账本条目与 act 环境，避免泄漏到下一用例。未删除实际用户缓存，也未添加用于生产的自动清理逻辑。

原有八个行为场景保留，其中 Markdown 场景迁至 `EditorQuitSource.test.jsx`。现在两份文件合计定义 15 个测试实例：TextEditor/桥接 13 个，Markdown 源码面板 2 个。输入法/保存队列套件使用 textarea 替身驱动真实 TextEditor 与退出桥接，不等于完整 Lexical 编辑器或 Electron 原生窗口测试。
