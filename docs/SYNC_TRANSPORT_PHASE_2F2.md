# Phase 2F.2 — WebDAV 读取故障恢复与错误信息保护

基于 Phase 2F.1 / 4.189.0 / schema 13。此提交只修改 WebDAV 传输层，包版本和数据库结构保持不变。完整同步任务的持久化退避尚未实现，不把本步骤描述为整个 Phase 2F 完成。

## 已接入现有请求入口

`WebDAVRemote.request` 现在使用有限读取重试策略，而不是新增另一个未被调用的工具函数。

- 只有 GET 和可重建请求体的 PROPFIND 可以重试。原请求加重试合计最多 3 次，基础等待为 1 秒、2 秒。
- 仅选择 408 / 429 / 500 / 502 / 503 / 504 和可判定的临时网络失败。认证、权限、证书、明确不存在的域名以及其他不明确错误均不会在本轮请求内重试。
- PROPFIND 每次使用新的请求体，同时保留认证、Depth 和其余请求头。
- 同一次请求的所有尝试、等待和最终响应体共享一个截止时间，沿用客户端的更短超时，最长 10 分钟；不会每次重试重置预算。该预算不是整个同步任务的总超时。
- 按 RFC 9110 §10.2.3 解析 Retry-After 的秒数和 HTTP-date。短等待不会早于服务端提示；超过 5 秒的提示不在本次请求中等待或缩短后重试，而是返回响应并保留结构化建议时间。大正整数溢出也不能变成零延迟重试。
- PUT / MKCOL / DELETE / MOVE / COPY / LOCK / UNLOCK 等操作不由此策略自动重放。原有内容哈希、下载 no-replace、事务、锁与冲突算法保持不变。
- 响应体已开始交付后的断流、哈希不匹配和损坏 manifest 不会在这里重新下载或掩盖错误。

## 错误信息保护

HTTP 错误不再把远端响应正文直接拼进界面/日志错误。`WebDAVHTTPError` 保留状态码、分类和 RetryAfterSeconds；`WebDAVTransportError` 提供安全说明并通过 Unwrap 保留底层类型供 errors.Is/As 使用，不在 Error() 中回显私有 URL、密码或服务端正文。

重试前和错误返回时不再为连接复用而读取未知错误正文，避免持续输出的错误页面拖住重试或取消。成功响应体仍由原调用者读取并关闭。

## 本次明确不做

这不是整个 `/sync/run` 的自动重放，也不是跨进程恢复的调度状态。

- 未改变 AutoTick 的任务级调度、自动同步开关、失败计数或跨重启行为。
- 长 Retry-After 目前仅保留在 Go 错误类型中，现有调度器尚未消费该字段；不宣称跨轮同步已经遵守长等待。
- 未改变同步状态 API / UI；上阶段的 30–300 秒 UI 状态读取退避与本次传输读取重试是两个不同层级。
- 请求帮助函数尊重传入 context 和共享截止时间，但未新增 Engine 到传输层的端到端取消接线。
- 远端锁租约、凭据迁移和已提交/未提交事务结果的恢复，仍须独立验收后才能引入任务级自动重试。

## 验证

本地已执行 18 个 Go 策略测试，含 9 种变更方法子用例；开启 race 检查并重复 20 轮通过；`go vet` 通过。

```sh
cd server/internal/syncengine
go test -race -count=20 webdav_retry.go webdav_retry_test.go
go vet webdav_retry.go webdav_retry_test.go
```

新增 7 个真实 httptest 传输入口集成测试，覆盖读取恢复、PROPFIND 只读、认证错误不回显、PUT 不重放、截断附件不发布、校验失败不重试、重定向不转发凭据。这些与原有 SQLite / WebDAV / Electron / Windows 回归以该提交 CI 的实际结果为准。本地环境无法联网安装仓库依赖，因此不能把独立策略测试称为完整后端测试通过。
