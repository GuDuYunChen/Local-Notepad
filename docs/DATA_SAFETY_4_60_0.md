# 4.60.0 — 数据安全整合交付

基线：feature/ui-redesign-v1，c99cf821e16dddc857c8ccbbd5c607fa02306c8f，源码与 4.53.0 一致。
本轮合并上一轮未推送的 4.54 统一备份中心，并推进到真实数据库操作，不再按每个按钮拆版本。

## 已实现的使用流程

更多／设置 → 备份与恢复。正文数据库与核对存档分别管理，不把两者误称为完整应用备份。

正文页签新增“立即创建备份”“校验完整性”“另存备份”。创建使用 SQLite VACUUM INTO 一致性快照；新文件通过 integrity_check 与应用结构／数据版本检查、同步文件后才发布。快照只包含已保存的数据库数据，不包含未保存的编辑器草稿、外部附件、核对存档或窗口状态。

校验回执含 SHA-256、数据版本和记录行数（含目录、已删除行）。每次刷新清除旧校验标记。另存使用系统保存对话框，实际写入并比对 SHA-256 后才报告文件已保存；取消不是成功，拒绝覆盖已有目标或将副本写回应用数据目录。来源在对话框期间变化则拒绝继续。

手动快照不参加自动清理。自动快照继续保留 100 份，修复本地时区解析与秒级命名碰撞；创建失败不触发旧备份淘汰。新的临时文件不出现在备份列表。

## 恢复安全

旧启动恢复先删除主数据库／WAL／SHM，再复制未验证的最新备份。本轮改为逐份校验候选，跳过损坏或高版本文件；先复制到暂存区复验，再把原文件移入独立 recovery-preserved 目录，最后以不覆盖方式发布恢复文件。无合格备份则保持原文件；中途错误尝试原位回退。

恢复标记在移动原文件前写入。主程序在打开数据库之前检查标记；异常中断或回退受阻时阻止下一次启动，避免自动创建空数据库。保留目录带 recovery.json 回执。此流程只在启动损坏恢复中执行，不新增运行中恢复按钮或 HTTP 恢复接口；不能据此承诺硬件故障、磁盘损坏或突然断电的零数据损失。

## 主进程与兼容

通过仅接受 create／inspect 的本地后端 CLI 完成数据库操作，不增加 HTTP 写接口。新 IPC 仅允许主窗口主框架调用，接受受约束的备份名称而非任意路径；不接受目录／符号链接。备份、校验和另存互斥执行，失败后可重试。

安装版使用随包后端。开发环境需先运行 npm run build:backend（生成当前系统的 server/bin/notepad-server 可执行文件）。旧后端缺少 CLI 时不声称操作成功。

4.54 的统一入口、核对存档保存状态、跨页整包备份、导入预检、焦点及关闭／重开保护一起保留。关闭中心不结束核对，不保存或覆盖正文；正在执行的文件操作不因关闭面板而撤销，但旧回执不会进入新面板。
