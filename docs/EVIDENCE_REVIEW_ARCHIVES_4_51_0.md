# 4.51.0 — 核对记录本地存档与安全恢复

功能基线：`8d374f1cdb4017bf43192ea5672bbef21789bba9`（4.50.0）。
开发分支：`feature/ui-redesign-v1`；未修改 master、数据库、正文或关系评分，不增加依赖。

## 使用路径

项目 → 结构 → 实体智能分析 → 正文证据回看。

在本轮记录或编辑器核对栏点击“保存本地存档”。返回正文证据列表，在“本地核对存档”中查看、导出、删除或恢复。默认按当前项目和实体筛选，也能切换到全部本地存档。

每次保存都是独立快照，不覆盖旧记录；后续备注、待修改项、已核对状态和当前章节变化不会自动同步。按钮提示当前快照是否已经保存；未存档的窗口记录仍会随刷新或关闭丢失。

## 恢复规则

恢复必须在对应项目和实体内明确确认，且当前不能有其他核对或待完成的核对打开操作。不覆盖正在进行的工作。

恢复备注、待修改项、筛选和当前章节位置；按最新证据数据恢复列表页。历史“已核对”仅保留在原存档及历史报告中，恢复后的所有章节需要重新核对，不将历史状态当成当前正文已审核。

原章节被删除或不再符合原筛选时，拒绝整个恢复，不静默丢弃对应备注；存档仍可导出历史 Markdown 或 JSON。当前筛选新增的章节会在确认中明确计数后加入，并重新核对。确认期间范围变化则要求重新预览。

## 存储与备份

- 使用当前浏览器／Electron 用户数据中的 localStorage，仅由明确保存或 JSON 导入触发写入，没有后台自动保存或网络同步。
- 仅保存 ID、标题、筛选、人工进度和备注，采用字段白名单、版本校验与不可变快照；不复制正文、精确定位快照或运行时令牌。
- 每份存档独立随机 ID 与存储键，避免多个窗口使用同一列表的读改写覆盖。订阅 storage 事件刷新列表；删除、恢复、导出前核对所选记录是否已变化。
- 最多 40 份存档，单份序列化文本最多 512,000 个 UTF-16 单位。超过限制或配额不足会明确报错，不自动删除旧存档、不清空当前记录。
- 损坏或不支持版本的存档在“全部本地存档”中显示为不可读取；不自动覆盖，可导出原 JSON 后处理。
- 删除需再次确认，只删除所选本地快照，不影响当前核对、正文或已导出文件。
- JSON 导出用于可恢复备份；导入创建独立快照、保留历史时间，校验完成后才写入，不自动开始核对。
- 本地存档不是云备份；清理应用／浏览器用户数据可能丢失，不随现有正文数据库备份迁移。跨机器继续还需原项目及章节 ID 存在；仅导入 JSON 不会创建正文或重映射 ID。
