## 复查与故障

当前 HEAD 与上次交付一致。重新读取 PR 和完整打包运行；从原始源码与两次累计补丁重建 Git 树 `37047f61b303d7a05854ae1e8570af3bb4498ec9`，与基线一致。完整本地 UI 1760/1760 和历史 Node 66/66 通过，不能据此忽略未覆盖的输入法事件。

查找框之前把每次 input 都直接作为已确认的筛选条件，并立即截断到 128 个 Unicode 字符。输入法候选期间，拼音会提前替换筛选条件；特别是在已有 127 个汉字之后输入 `zhong`，受控输入框只留下 `z`，候选文本在确认前已被改写。旧测试只验证普通 input，不包含 compositionstart/update/end 与长度上限交错。

新增真实 React 事件场景，在精确的旧组件上复现 8 项指定断言失败，6 项对照通过。基线复现脚本检查组件的 Git blob 摘要 `8fb1adfbce5808d0f075f0c47ad95f6cead94521`，拒绝用超时、加载错误或运行时异常冒充产品缺陷。测试中组合事件的跨浏览器顺序变体，不等同于某个物理输入法现场复现。

## 修复

查找框区分“输入法当前候选文字”和“已确认查找文字”。候选内容保持原样，不在组合期间截断；已读取记录继续按上一次确认的条件筛选，并显示“输入法文字尚未确认”。输入法确认时才应用 128 字符上限和新的查找条件，仍不拆开 emoji 的代理对；普通英文字母输入仍即时筛选，没有新增确认按钮或业务弹窗。

完成组合或移出输入框时处理当前输入；清除本地筛选会同时清除组合状态，迟到的 compositionend 不得恢复旧条件。追加页面和刷新失败不会把候选文字误用成已确认查询。卸载后不保留查询或组合状态。

仅查找框改变。自动保存、Ctrl+S、引用维护、保存回执、数据库、凭据、同步执行和真实未保存退出保护都未修改。查找仍只覆盖已读取的记录，查询不进入 GET URL、不落地存储，不搜索历史正文，不改变服务器筛选条件。
