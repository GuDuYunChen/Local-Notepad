## 本阶段边界

新增 `src/hooks/useS3ReadProbe.js` 与 `src/services/s3ProbeBinding.mjs`，为2F.42既有会话提供React挂载、订阅、输入版本失效和卸载清理的调用契约。只在显式`read(payload)`时走既有原生桥，构造/订阅/连接/渲染/输入版本变化都不读取对象。没有挂入同步中心设置表单，没有可见S3控件、凭据保存、provider、List/上传删除、自动同步或真实桶访问。

这不是新S3网络客户端，也不重写2F.42请求和响应校验。原生main/Go继续负责目标、签名、生命周期取消、总时限和传输并发。React停止等待仍不等于原生I/O已取消；重新挂载不会绕过原生全局单并发限制。

## React 调用契约

`useS3ReadProbe(revision = 0)`返回`{result, read, invalidate}`。revision必须为非负安全整数，仅用于标识输入/上下文版本，不接收或保存配置、对象键或凭据。调用方在输入/目标/上下文变化时增加revision；对于延迟或并发渲染，编辑事件处理器应先直接调用invalidate，不能等到未来提交才使旧结果失效。此hook不自动深比较任何尚不存在的表单。

通过useSyncExternalStore订阅冻结的脱敏视图。snapshot在没有状态变化时保持同一引用，read/invalidate函数在普通重渲染时保持稳定。布局effect建立一个已提交的挂载生命周期；清理只关闭属于自己的会话，不终止网络进程。React StrictMode的setup→cleanup→setup会重建已提交会话，不复用永久disposed会话，也不会在effect中发起检查。未提交的渲染不打开会话，不会读取对象。

只渲染`result`中固定解释和脱敏摘要。缺少原生桥直接不可用，不改走fetch。权限解释沿用2F.42：403/404及公开对象可读不验证凭据有效、List/写权限或同步完成。

## 绑定层生命周期和异常

绑定层`connect()`只由组件挂载effect使用，返回幂等的所属生命周期清理函数。仍连接时重复connect明确失败，不重置当前检查。清理后的旧read函数返回固定disposed结果且不读取输入属性；旧清理和旧Promise回调不能影响后来的连接。

订阅不携带请求或原响应参数，观察者从snapshot读取最新状态。同一回调的两次订阅可独立取消；取消后不再通知。观察者抛错被隔离，不会把原生结果转成未处理的Promise拒绝；观察者引发输入失效/卸载时，回传结果也再次校验所属生命周期。观察者负责避免自身无条件循环更新。

重复调用的busy结果返回给该次调用者，但不覆盖仍在进行的可见pending状态。输入失效/等待超时按原会话保留未结束的原生调用槽；迟到结果被消费但不发布。组件卸载dispose原会话，清理计时器；下次挂载没有自动重试。没有轮询或新增取消IPC。
