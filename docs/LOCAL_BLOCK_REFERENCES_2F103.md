## 基线与完整范围

本模块在原编辑器增加一个“块引用”入口，从创建稳定来源、核对保存、复制地址，到预览、再次核对、插入、保存、重开、更新来源、导航、删除失效和停止读取形成同一工作流。不是只有一个解析工具或未接入的组件。

## 使用流程和保护

1. 把光标放入顶层段落、标题、引用、列表、代码或表格，打开“块引用”。“为当前块创建引用”仅通过原 Lexical 更新产生普通草稿，沿用原自动保存、Ctrl+S、版本历史和退出保护。不发送另一套保存请求。
2. “核对保存并复制引用”读取本机真实已保存正文，要求该块完整序列化内容与当前草稿一致。未确认保存时拒绝复制；剪贴板不可用时保留经核对的只读地址供手动复制。
3. 在目标笔记放置光标，粘贴 `notepad://block/<笔记ID>/<稳定块ID>`，读取来源。预览不写任何笔记；确认时再次读取，来源正文或标题已变化则更新预览并要求再次确认。
4. 行内引用保留来源笔记和块的精确身份。只读嵌入显示来源的保存版本文字，并有“刷新来源”“停止读取”“打开来源块”。打开沿用原保存／放弃／取消决定，不绕过草稿或待应用字段保护。
5. 同一来源中的普通编辑、重命名和原块拖动不按文字重猜身份。复制／粘贴或复制块去除自身锚点，防止两个源块共用身份；嵌套引用的目标身份保留。剪切后粘贴属于重新插入，跨笔记移动也不会暗中重定向原引用。
6. 来源被删除、移出原笔记、锚点重复或内容类型不支持时明确报错，不挑选相似段落，不保留陈旧嵌入当作最新结果。原笔记恢复后可明确刷新。

## 内容边界

锚点以 Lexical NodeState `localBlockId` 保存在正文中，数据库 schema 仍为14。旧 WikiLink 序列化形状保持；新 `blockId` 和 `embedded` 字段需严格有效，不把损坏字段静默降级成普通笔记引用。

支持7种顶层块类型：paragraph、heading、quote、list、code、code-block、table。真实自定义代码块保存／重开保留 NodeState；代码框只提供来源引用，插入前须把光标移到普通正文位置。

嵌入是**只读文字投影**，不是第二个可编辑富文本副本。表格有制表／换行分隔，代码保留原文；图片、附件、外部嵌入和内部嵌套引用显示说明或引用标识，不加载远端媒体、不递归展开，因此循环引用不会触发递归读取。打开来源可查看原有富文本控件。

读取正文上限2MiB、递归深度64；单块展示上限20,000字符／2,000节点。超限、未知节点和错误字段全部明确拒绝，不截断后声称完整。嵌入共享最多4个进行中的读取、64个排队请求；关闭、切换、停止和阅读模式变更使旧请求失效，不自动重放写入或启动后台刷新。

Markdown源码编辑对于含锚点的正文明确标为不支持，避免不知情地丢失身份。Word/Markdown导出仍输出引用标识并给出未展开来源的提示，不宣称导出的文本是块引用备份或已复制来源内容。完整工作区便携包保留原正文数据；没有修改便携包或恢复协议。

## 导航、生命周期与异常

源笔记读取、原选择保护、正文加载完成和块定位各有独立条件。跨笔记必须等对应正文的真实编辑器就绪；切走、重载、正文改变、撤销保存或导航代次变化都会废弃旧定位。相同笔记只定位当前真实块；不先更改选择或清空草稿。

预览、嵌入和复制核对都保留请求所有权与 AbortSignal。确认期间目标正文变化，原插入位置失效；停止之后的响应不会插入或复活界面。错误文案不透传底层网址／堆栈。`notepad://` 只作为应用内引用值解析，不交给浏览器或系统打开外部网址。

## 本轮发现的问题与修复

- Electron31 的 Chromium 将未注册的 `notepad://` 解析成 opaque path，而 Node／happy-dom 会提供 host。真实开发版中合法地址因此被拒绝。改用应用自身严格的规范语法并验证编码往返；保留路径、查询串、外部协议和错误身份的拒绝用例。
- 自定义 CodeBlockNode 原先没有把基础 NodeState 纳入序列化；本模块补上 import/updateFromJSON 和 super.exportJSON，以真实 Lexical 重开测试证明锚点保留。
- 引入块定位时复用原标题导航就绪事件会提前消费请求；现在分别等待块和标题的对应事件，并绑定正文和导航代次。
- 新安装包装器最初仅比较旧 gate 的索引，`-1 < anchor` 不能证明旧 gate 存在。确定性负例暴露后，补充旧 gate 恰好出现一次的检查，保留全部28门并追加第29门。
- 原生截图须等待真实临时通知消失，避免通知覆盖引用预览；不删除通知DOM、不改计时器。小窗口和深色截图由真实Windows窗口助手与主题按钮取得。
