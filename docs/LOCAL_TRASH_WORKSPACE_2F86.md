## 完整使用链路

更多 → 回收站 → 读取/失败重读 → 本地搜索、类型/到期筛选、排序、分页和明确选择 → 恢复确认或输入“永久删除”确认 → 再次核对项目 → 逐项处理 → 持续显示成功、未确认、未执行 → 手动核对/恢复 → 关闭及重新进入。

读取失败不显示为空；筛选无匹配不等于回收站为空。已成功操作不会因为刷新失败或父列表回调失败而变成失败，也不会因此重发。任意未确认回执停止剩余请求。超时/中止不宣称后端回滚；迟到回复不把未确认记录改成成功。

停止或离开页面会阻止尚未发送的操作。发送前检查覆盖“行状态已更新，但真正请求尚在微任务队列”的窗口及单调截止。已经发送的请求仍可返回自己的真实回执；不自动继续剩余项目。

清空仅处理确认时选定的顶层 ID，不使用 DELETE /api/files/trash。确认后新增的其他顶层项目不在范围内。文件夹仍按既有后端的递归规则处理，子项以执行时为准；这不是目录子项的事务快照。操作记录只保留在应用进程会话，不承诺崩溃或重启后恢复。收起结果、执行下一批及关闭/重新进入面板，不会静默丢弃未确认回执。

## 回执保留与容量

不可变会话历史在收起和开始下一批时保留旧报告，查看不会联网、重放请求或重复发出恢复回调。后来的成功不能改写早先未确认的结果。

最多保留 20 份已收起记录及一份当前报告。超出历史容量时只淘汰最早且没有未确认结果的记录；所有槽位都被未确认记录占据时，拒绝新批次（包括预检），而不是静默删掉未知结果。有在途请求时不允许移除记录。用户移除未确认记录须单独确认结果仍未知；移除只是本地元数据变更，不解决结果，也不自动恢复先前拒绝的操作。
