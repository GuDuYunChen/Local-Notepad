## 先复核，再修复

精确重建并核对上一阶段源码树；原交付包40项内容摘要、8项原生桌面检查及两个正常关窗回执重新通过离线核验。当前远程PR仍在a6675cf，没有重复开发或重跑已成功的远程任务。62项阶段核验和18项原窗口会话测试先通过。

检查异常路径时，发现窗口助手只给stdin安装了error监听。stdout或stderr发生流错误，会从EventEmitter直接抛出并终止测试进程，不会转成已有的有界请求失败。对启动中、等待inspect中、已清理三个阶段分别在两个真实Node流上注入ECONNRESET，共六个独立子进程全部exit 1并输出未捕获错误，包含原错误字符串。这里使用的是隔离模拟子进程接口/真实Node流，并未声称实际破坏了Windows管道或用户工作区。

另发现dispose取消待处理请求后、助手退出前，迟到的正常回复仍被解析成意外回复，导致额外终止助手。原测试只覆盖清理完成后的迟到结果，没有覆盖清理尚未完成的窗口。

## 修补边界

三条管道均安装错误监听并保留到生命周期结束。活动期间错误统一变成固定PIPE_ERROR，拒绝ready或当前请求，标记不可复用并只结束自身助手；不打印原始路径/异常正文、不重建助手、不重发WM_CLOSE、不改应用保存保护。

主动清理开始后丢弃迟到的输出数据，不再解析或累计到缓冲区；已取消请求不能被迟到成功回复复活。真正的管道错误发生在清理完成前会记为非干净退出，即使助手随后以0退出也不能宣称正常；清理完成后的迟到流错误仍被消费，不重新打开会话或终止测试宿主。

预热30秒、请求10秒、应用退出15秒和未加速自动保存计时保持不变。PowerShell脚本、目标窗口复核、独立报告校验器、全部工作流预算与权限不变。没有变更src/electron/server、package.json/package-lock.json、依赖或schema。
