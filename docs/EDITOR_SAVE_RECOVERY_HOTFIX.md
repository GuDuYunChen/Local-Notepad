# 修复正文保存与引用维护互相阻塞（4.189.1 / schema 14）

## 范围和原始故障

本轮仅修复用户已经报告的自动保存、Ctrl+S 与退出问题，不进入下一功能阶段，不合入 master。基线产品提交为 `0b66c7e6a902129cd2ead4da75f5d1bf96a9d9de`；`b7edf79` 仅准备真实源码和测试依赖，没有修复产品。

旧实现的结构变化会跳过定时保存，手动保存则在正文写入前扫描全库、等待引用确认和请求快照。上一轮“不保存”草稿登记修复不覆盖这些路径。已增加真实 App/TextEditor 用例，在精确旧代码上分别复现“结构 Ctrl+S 未保存”和“结构定时保存未保存”，不是把正常的退出保护失败算作复现。

## 正文保存路径

自动保存、Ctrl+S、退出时的正文保存共用同一个保存队列，但不再以跨笔记引用扫描/对话框/网络快照为前置条件。结构变更与普通正文一样提交到本地数据库。

编辑器请求携带不可变的请求编号、预期数据库原文、目标正文和结构映射。后端在同一个 SQLite 事务内比较原文，保存旧版本、写入新正文、更新本笔记的链接索引，并记录成功回执；结构变化同时持久化后续引用维护的旧/新正文及映射。不是先保存正文、再寄希望于内存定时器记住引用更新。

客户端等待最多 8 秒，后端事务上下文预算 5 秒。等待超时不视为事务回滚或保存成功。重试先携带同一编号和同一内容核对；后端已提交时只返回该请求回执，不重放旧正文。只有旧请求获确认之后才允许提交更新的编辑。预期原文不匹配时拒绝覆盖较新数据库正文，草稿保持未保存。重复请求不会重复添加版本快照。

实际 id、正文和请求编号全部匹配才接受保存成功。仍未确认的写入不能通过“不保存”或退出被悄悄丢弃；没有全局清空退出登记，也没有以 AbortSignal 充当数据库回滚证明。

同字数正文修改也更新状态。Ctrl+S 保存前后文档发生变化或用户继续编辑时，不把旧回执当作最新正文已经全部保存；界面给出区分。源码模式未应用编辑、输入法组合、未确认写入和后端退出保护仍保留。

## 引用维护

独立维护器在启动和已提交结构变更事件后读取数据库待办，使用现有引用分析函数，只对可唯一确定、来源原文仍一致且无活动草稿的来源执行修复。后端再次比较目标和所有来源，快照与全部来源变更在单个事务提交。失败保留待办，不回滚或阻塞已经保存的目标正文。维护待办随数据库备份/恢复及应用重启保留。

无法唯一判断、多次结构编辑导致待办目标已变化、来源有草稿或自身引用，需要保留待处理，不能猜测改写；当前版本不声称能自动合并所有连续重构链。可通过独立状态提示重试引用更新。仅引用待处理不阻止退出，正文未确认仍阻止。改名/删除等其他显式重构操作的原有确认未移除。

## 兼容性与数据安全

增加 schema 14 的 `editor_save_ops`，不修改既有笔记正文格式；支持从 schema 13 正常迁移。更新备份校验和 Electron 数据安全层的支持上限，旧版本不得打开升级后的数据库。安装前备份工作区；不能把降级至旧程序当作回退数据库的办法。

版本 4.189.1 用于区分此前同为 4.189.0 的未完整修复构建。前后端必须一起构建更新。旧后端缺少新回执时明确不确认成功，不能把只替换前端作为部署方式。

已完成维护的回执只保留元数据和请求摘要，不重复长期保留全文；待处理任务保存必要旧/新内容。永久删除笔记时触发清理对应任务正文和回执元数据，保留编号防止迟到旧请求复活内容。普通版本历史仍限制为最近50条，不能以历史裁剪删除未处理任务的映射。

- 实际 SQLite：回执幂等、比较后写入、部分事务回滚、引用失败保留任务、删除清理、迁移/备份。
- 单独端到端测试使用真实 App/TextEditor、真实 Go HTTP 和迁移后的临时 SQLite；只替换无关导航和富文本输入。引用扫描故意失败，保存正文后发起真实渲染器退出握手，再通过与 Electron 相同的父管道关闭 Go 服务，重启服务和 App，清除渲染器草稿缓存后核对正文仍在。自动保存测试驱动已注册的30秒回调，不冒充等待真实30秒的物理操作。
