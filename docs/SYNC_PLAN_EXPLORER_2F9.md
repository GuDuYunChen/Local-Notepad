## 用户入口

同步中心点击「预演同步」，或已展示计划中的「重新预演」，通过原有只读预演接口获取快照。原来的四项数量汇总升级为完整明细浏览：方向筛选、对象编号 / 附件名搜索、每页 20 项，能到达末页。默认显示有变化和冲突项，「全部对象」和「无变化」可以查看其余内容。筛选与翻页不发送请求。

上传 / 下载方向直接使用服务端分类，不在前端重做三方合并。接口没有文件标题和具体文件 / 文件夹类型，因此明确显示「笔记 / 文件夹」及真实编号；不臆造标题、路径或删除状态。标签关联保持原始编号，不拆解可能含冒号的 ID。附件名称从既有十六进制 ID 解码，非法编码、无效 UTF-8 或不安全名称回退到原始编号；不读取附件字节、不打开文件、不执行任何标记。

## 不是“确认后执行此计划”

- 预演显示生成时间和「预演快照（只读）」。不持续跟踪远端或编辑器变化，执行同步仍由后端重新计算；计划不是写入授权。
- 执行接口返回的 plan 显示「执行时计划（历史）」，不当作剩余任务或已提交数量。needs_init 也以当时的状态描述，不把历史初始化当成将来动作。
- 观察到目标、设备、远端修订、同步状态变化，状态读取失败、配置草稿变化、后台任务结束或启动另一项操作时，旧快照失效并保留对照。变化计数也保护正在等待的预演结果；A → B → A 不会恢复旧快照。
- 只有新的成功响应能替换旧快照；新预演失败保留已失效的旧内容，不自动重新预演。未保存配置时两个预演入口均禁用；状态刷新不覆盖草稿。
- 既有「执行同步」、写入结果待确认提示、acknowledge_uncertain、冲突对照与最终明确选边保持原流程。明细组件没有 run / resolve / 文件打开 / 凭据写入能力。

## 数据边界

数量必须是非负安全整数；完整明细必须逐条验证唯一 ID、方向、条目数量和四类计数一致。无效响应不能显示成“0 个”或部分成功明细。兼容 Go 空切片的 `items: null`，但缺失明细不等于空计划；旧版汇总响应会注明“仅为服务端汇总，不能核实每个对象”。

明细上限 50,000 条，单个 ID 上限 4,096 UTF-16 单元，ID 总预算 8 Mi 单元。超大计划明确降级为未核实的服务端汇总，不静默截取前若干项。搜索最多 256 单元，支持 NFC / 大小写归一和字面匹配，不把输入作为正则。搜索无结果与整个计划为空分别提示。

快照只保留用于显示的白名单字段并冻结，绝不保存正文、密码、任意服务端附加字段或哈希。目标观测键仅保留在父组件内存引用中，不渲染、不持久化、不导出。没有新增 localStorage、文件写入、网络端点、遥测或导出功能。

计划展示错误使用显式错误模型；执行已返回成功后的 plan 展示异常，不会被包装成同步写入失败，也不会导致自动重放。
