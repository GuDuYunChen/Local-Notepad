# 4.180.0 — 研究草稿、创建查回与同任务安全重试

基线：`feature/ui-redesign-v1` / `54a929ff756ca48baa02610ac08cca7b3a5254c2`（4.170.0）。继续原分支，不改 master，不新增依赖。前端和 Go 后端需要一起更新。

## 完整使用流程

全局检索 → 阅读批注 → 跨页选择已存批注 → 整理成研究笔记 → 预览 → “保存研究预览草稿”或“确认创建独立研究笔记”。保存草稿不发送 HTTP 创建请求；确认创建先保存同一任务的完整历史草稿，再请求后端。已经单独保存的预览会复用原任务 ID，不再新建另一任务。

新增“研究草稿与创建记录”入口，和批注来源汇总独立：即使来源资料集已移除，也能检查以前明确保存的草稿。支持完整历史预览、下载 Markdown、查回任务结果、明确确认同任务创建或重试，以及二次确认移除本地任务。打开查回的笔记仍走原 App 的保存／不保存／取消保护，不自动覆盖当前正文。

已保存草稿持久化于本机，最多 10 份、每份 3 MiB；正文仍受 2 MiB、200 条批注限制。容量满、锁不可用或写入失败时，不发送新的创建请求，不自动清理旧任务。格式损坏的条目明确显示并计入容量。预览前尚未保存的标题、目标和选项不在本功能的持久化保证内。

## 创建身份与数据库事务

新增 `GET /api/research-notes/{requestId}` 与 `POST /api/research-notes/{requestId}`。任务 ID 是规范 UUID v4，绑定确定的标题、目标目录和完整 Lexical JSON。指纹为 UTF-8 编码的 `title + NUL + parentId + NUL + content` 的 SHA-256；前两项不允许 NUL。路由身份不接受 JSON 或查询参数覆盖。

数据库增加第 10 版迁移 `research_note_requests`。同一事务中的第一条 SQL 预约任务主键，随后验证整个目标目录链，并一并创建笔记、来源 WikiLink 元数据和回执；提交失败全部回退。查询不创建记录，不按标题猜测成功。重试同一任务和相同内容返回原笔记 ID；不同内容被拒绝。相同任务在独立连接并发请求也由 SQLite 写事务和唯一主键协调。

笔记后来被改名、编辑、移入回收站或永久删除，不会被重试覆盖或重建。回执保留原创建身份；查回同时报告当前笔记可用、回收站或已缺失。正文被修改不影响查回原创建事实，不声称原研究内容仍是当前正文。

新版本备份检查支持数据库第 10 版，并验证回执表可读取。新增更高数据库版本拒绝启动检查。升级现有数据库只添加回执表，不重写已有正文；不要将旧版本程序用于已升级数据库。正式研究笔记和后端回执随数据库备份保存，但本机研究草稿任务不在 `.db` 备份中。

## 中断与恢复边界

提交前先记录本地“已发送”状态。响应丢失、超时、关闭窗口不能证明后端没有写入；任务会保留为“待查回／结果待确认”。新窗口或新进程可以从本地任务查回，不自动重新 POST。用户明确重试时先 GET；只有当前数据库没有回执才按同一 ID 和原内容发送。后端提交过的相同任务不重复生成文件。

服务端确认后，即使本地回执保存失败，也报告“服务端已确认、本地记录未保存”，而不是误报创建失败。再次查回无需重新创建。本地已知成功但当前数据库没有回执时拒绝再次创建，提示检查是否切换或回退了数据库。

从实时批注预览创建时继续检查源快照、所选未存草稿和目录。重新打开已存任务时使用保存当时的完整历史草稿，必须明确确认，不偷换为当前批注，也不承诺来源仍存在或批注仍与最新正文相符。历史草稿不可在原任务下改写；新内容要作为新任务另存。

防重复保证限于保留了该任务 ID 的同一数据库历史。切换、回退或损坏数据库，移除本地任务后另建新任务，都不提供全局去重保证。取消客户端请求不是撤销服务端事务；仅在事务实际提交前失败时才不会有新笔记。回执不自动清理，未提供用户界面回执删除功能。

本地任务的单条保存采用原子 setItem、Web Locks 和原始字节比较；这不是本地存储与后端 SQLite 的跨存储事务，不承诺断电或磁盘损坏恢复。Markdown 下载不携带可重试任务身份，不能替代任务迁移。文件与草稿未加密，包含私人批注；移除本地任务不删除正文或服务端回执。
