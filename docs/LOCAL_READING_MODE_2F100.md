## 本次接续与复核

基线 `573758ffc9899c2ad1cdef6e949f9667e45ad55e` /4.233.0 的原17项CI已成功，原Windows报告覆盖普通正文的阅读切换与保存。独立复核仍在原代码上复现以下缺口，因此在同一个2F.100模块修补到4.233.1，不把旧绿灯作为本次验收。

- Lexical根区域的只读状态没有自动保护Decorator节点内的独立控件。待办、提示块、折叠块、代码、公式、嵌入、图片、图集和附件均须监听真实editable状态，同时保护事件入口与实际editor.update写入。
- 移除OnChangePlugin会漏记切换前已接受、但尚未完成Lexical协调的编辑。现在内容观察器跨模式保持挂载，切换本身仍不制造内容修改。
- 常驻观察器还必须区分内容加载与用户编辑。空正文及旧有效JSON的加载归一化使用显式标记，只更新去重基线，不制造未保存草稿；加载前先交付已接受的用户编辑，加载独立提交，避免把用户输入合并进忽略的加载事件。
- 上传和文件选择须绑定发起时的编辑会话。进入阅读态、切换笔记或卸载即失效，之后返回编辑不能复活旧结果；普通编辑态的合法上传保持。已发出的上传HTTP不等于可被取消，但失效结果不能再写正文。
- Wiki候选、资源移除、Markdown源码应用和链接弹层旧回调都要在执行时重新检查可写性。源码未应用草稿保留；关闭需明确确认丢弃，取消继续保留草稿及退出保护。
- 链接弹层读取使用Lexical0.51所需的活动编辑器上下文；阅读态显示、打开和复制均使用已保存链接，不能暗中使用未应用的编辑草稿。

折叠块展开、文本选择、查找、链接导航、代码复制及图片/附件预览下载仍可用于阅读。折叠块在阅读态的展开只改变当前视图，不写入笔记。

## 阶段目标
在现有 Lexical 编辑器中提供可切换的阅读模式与编辑模式，先完成本地体验；不开发云、多端同步、更新或推送。

## 实施范围
- 编辑器通过 Lexical 的 `setEditable` 切换，不用 CSS 伪装只读。
- 阅读模式保留文本选择、只读查找、Wiki/普通链接和目录导航；编辑工具栏、写入插件与自动聚焦仅在编辑态启用。
- 阅读态独立调整正文留白、宽度、段落和标题间距，窄屏收紧边距；继续使用已有字体、行距、正文宽度偏好。
- 模式偏好保存在本地；读取损坏或不可用时回退到编辑态，写入失败提示用户但不阻断本次会话。
- 切换模式不卸载 TextEditor、不重载正文、不触发保存或丢弃决定。未保存正文在阅读态明确提示仍被保留；自动保存、冲突处理、退出保护与重试逻辑不另建一套。
- 空白笔记在阅读态使用只读空态文案。
