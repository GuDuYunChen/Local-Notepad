## 功能与数据范围

同步总览底部新增默认收起的“冲突处理记录”。挂载、展开、父级状态更新都不读取；点击读取，或明确更换筛选条件，才发起本机只读请求。可以查看已选边处理和已失效的记录，按处理/失效时间从新到旧浏览，每批 25 条，按需读取更早记录。

“已失效”不等于“已解决”；重新绑定导致的失效与历史选边分别说明。当前笔记标题仅用于辨认，不冒充当时的标题或正文。已删除对象仍可通过记录标识辨认；非文件对象显示类型。所有文本由 React 转义，不渲染任意 HTML，不自动打开链接。历史页面不提供恢复、重新解决、删除或同步执行按钮。

记录属于本机工作区，可能包括旧同步目标的历史；不是所有同步操作的日志，不保证当前远端状态，也不保证历史保留版本现在仍相同。仅给出已加载条数，不将其解释为全部历史总数。

## 后端接口

新增 `GET /api/sync/conflicts/history?filter=all&limit=25&before=...`，filter 白名单 `all / resolved / superseded`，默认 25、最大 50。使用 `(resolved_at, id)` 降序游标分页，不用 OFFSET。相同时间的记录有确定性次序，新记录不会挤移已捕获游标以下的页面；新产生的上方记录需要重新读取。

沿用 schema 13 的 `sync_conflicts`，只投影记录标识、对象标识/类型、当前标题、两个时间、状态和白名单化处理方式。SQL 不选择历史正文、对象哈希、账号、密码或远端端点，不创建远端对象、不锁定同步引擎、不写表。后端读取设置 3 秒上下文预算，忙碌/损坏/参数错误以固定错误返回，不能伪装成空记录或泄漏数据库错误。没有新增迁移和持久化键。

## 前端读取与交互边界

使用独立、可取消、最长 8 秒的读取；停止等待读取不是取消同步。筛选变化/关闭组件废弃旧请求，即使底层忽略 AbortSignal，晚到响应也不能重新显示。相同筛选的刷新或后续页失败保留旧记录，明确标注旧读取；改变筛选后的失败不混入旧条件的行。重复行、倒序错误、游标未推进和不完整响应被拒绝。

读到末尾后，已消失的“更早记录”按钮的焦点转回记录列表；主动停止后回到读取按钮。普通状态刷新不移动焦点、不发请求。只对本组件设置样式和焦点提示，不修改总览状态推导、五个分区导航、时间偏好、帮助、同步/冲突处理/凭据或退出保护。

## 本轮开发中修正的边界

新增测试先发现：255 个 Unicode 字符中的 emoji 会被 UTF-16 长度误判；同一轮事件中立即中止时，已排队的读取微任务仍可能调用加载器。分别改为有上限的 Unicode 字符计数，以及在调用加载器之前再次检查中止。两项失败已复现并修复，不是删掉测试。
