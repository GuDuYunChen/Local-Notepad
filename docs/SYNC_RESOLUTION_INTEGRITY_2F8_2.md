# Phase 2F.8.2 — 冲突选边后的目标结构校验

## 先修复，不叠加业务功能

基线为 `658208b50940f519683a87ff5c82eef50e26827f`，上一轮 push #1225 的 Linux/Windows 均成功。继续复核发现 Resolve 路径缺少选边后的整体目标结构校验：两端各自合法，并不意味着把某一个本机版本放进远端（或相反）仍合法。原路径会直接发布/应用选中对象，可能出现同目录重名、标签大小写重名、目录循环或删除父目录后遗留子项。

这不是上一轮 CI 失败，而是未覆盖到的边界。修复集中于冲突执行路径，不新增自动合并或新 provider。

## 正式修复

- 在远端锁内重新读取并检查已绑定的远端身份和当前清单结构，避免仅依赖获取锁之前的预检。
- 保留本机时，在上传所选对象/附件和发布清单前构造候选清单，复用既有结构规则验证。候选校验不需要先上传所选对象；不合规时保留原清单、内容、基线及待处理冲突。
- 采用远端的数据库对象时，在同一个 SQLite 事务里重读本机对象与基线、重新核对被选笔记的本机哈希、验证候选本机结构，再应用正文和推进基线。基础写入失败会一起回滚正文/历史版本与基线，而不是正文已提交、基线失败。
- 本机候选校验准确模拟现有文件/标签永久删除对标签关联的清理，不新增目录递归删除。不允许孤立子项；用户应先处理子项或其它依赖冲突。相关冲突按安全顺序选择仍可完成。
- 附件保留原有独立文件保全路径，不把 SQLite 事务说成能回滚附件字节。结构不合规时在移动本机附件之前拒绝。
- 预检后的恢复协调器仍保守保留已有的“写入结果待确认”边界。获取/释放远端锁本身可以写远端，不能将整个被拒绝操作称为完全只读；不会因为这次验证失败而自动清掉恢复记录或重试写入。

## 测试

新增 6 组纯校验测试和 8 组实际引擎/事务测试（含参数化场景），专项统一以前缀 `TestResolutionGuard` 执行。

覆盖两端合法但单项组合无效的正文重名、目录循环、标签重名、父目录删除；相关冲突按正确顺序完成；已绑定远端身份在预检后改变；清单对象键与实际记录 ID 不匹配；本机较晚编辑不能被旧选择覆盖；注入基线写入失败时正文/历史/基线一起回滚；原恢复记录语义不被绕过。

拒绝测试比较两端受保护对象、清单、全部本机对象、基线、待处理冲突和历史版本数量，排除正常获取/释放的锁文件。此前的生命周期、前端确认和退出保存测试均保留。

CI 新增 Linux race 三轮及原生 Windows 专项，其余门禁、顺序及 18/30 分钟预算不变。
