`node scripts/stage-review.mjs ci <runs.json> <fresh-branch-head>`：只读取已取得的GitHub Actions `workflow_runs` API JSON快照；HEAD必须另外从当前分支核对。输入最大2MiB/200条，输出固定10项摘要，退出码0为这份快照中CI完整、2为缺失/进行中/失败、1为输入错误。它不联网、不轮询、不自动重试、不修改文件或仓库。工具返回的简化包装若缺少HEAD/event/path等字段必须重新取得正式快照，不能猜填后当成工具原始证据。

检查范围固定为八条pull_request流程，加push的UI Redesign完整打包和Desktop Save端到端。按工作流路径、事件、仓库、分支、HEAD匹配；只认该流程最新run，旧成功不能覆盖新失败。同一run混入多个attempt快照会拒绝，提示重新读取一份一致快照。会保留较早失败run的编号与最新attempt。

**全部CI成功也只输出 `artifact-verification-required`，从不输出“阶段验收完成”或“可合并”。** 还须人工核对PR测试树与分支、原始报告完整性、安装包/原生文件和需要的图像。快照可能过时或被编辑；本工具不做来源认证，也不证明当前远程状态。

## 防止重复触发长链路的执行约束

1. 恢复时先读HEAD和交接，不先创建分支、重新提交或重跑成功任务。写入没有回执时先读远端，不能猜成功，也不能猜失败。
2. 先选相关问题和回归文件，形成短计划；运行完整测试前确认依赖锁和本地条件。缺少Windows/网络就据实限定范围，不反复进行同一失败clone/install。
3. 长日志/测试报告存文件，普通进度只返回HEAD、阶段、通过/失败/待验收、剩余项。先取job步骤定位，再取特定失败job日志；不反复抓全仓diff、整个PR讨论或全部工作流日志。
4. 同一输入不变的失败不盲目重试。新证据证明为临时环境异常后，只重试相关失败job一次并保留旧attempt；再失败就停在待处理检查点。不要为了绿灯去掉断言、降低对比度、允许过时回执或强制退出。
5. CI轮询应隔开并仅关注未完成run；本工具本身不提供轮询器。状态未变化就不重复下载同一产物，产物按ID/HEAD/摘要核对，不按文件名猜路径。
6. 源码推送后、CI完成后、产物独立核验后三个节点各留检查点。PR评论/更新被拦截时不绕过或连续换工具重发；保存本地接续文件并明确远程未写成功。检查点不能宣称未进行的验证。
7. 先完成修补与验收再开发下一功能；单轮不同时叠加多个功能。原有回归和工作流预算不减少，正常工作仍在原feature分支，PR #2保持Draft、不合master。

这些约束减少重复工作和大载荷，不能保证聊天平台永不中断。npm404、PowerShell查询超时、工具安全状态拦截和“无法思考”必须分开记账；没有内部错误码不能声称已找到或修复聊天中断根因。

## 本轮新增检查器的分页覆盖补修

592af5d候选审查中，合成反例发现仅提供10条绿色记录、API却声明total_count为11时，检查器仍会给出ciComplete:true。它不是新发现的应用保存故障，也不是一次实际CI成功证明。原始反例输出保留在本轮交付记录。

修补后要求total_count为非负安全整数且与实际提供条数完全相同；缺失、非数字或数量不一致均输出coverageComplete:false、ciComplete:false、not-ready，即使眼前10项全部绿色。它不会自行翻页或猜测未取得的记录。新增4项覆盖反例，本轮共47项新测试。多run成功对照补齐其原本遗漏的准确total_count，不减少任何失败断言。源码身份、分支、路径、最新run及产物待核验要求不变。
